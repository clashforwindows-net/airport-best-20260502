## 一、为什么懂架构才能选对机场

很多人买机场翻车，不是因为运气差，而是因为**用错了评价指标**。

| 你以为重要的 | 实际决定体验的 |
|------|------|
| 节点数量多 | 节点背后的线路质量与回程 |
| 价格便宜 | 单位带宽成本与超售比例 |
| 宣传"无限流量" | 单机承载用户数与限速策略 |
| 客服态度好 | 故障切换是否自动化、有无热备 |
| 标称"1Gbps" | 入口带宽、中转瓶颈、TCP 优化 |

一个残酷的事实：**同样叫"香港节点"，可以是直连 CN2 GIA、可以是公网中转、也可以是 IPLC 内网专线，三者体验差 5 倍以上，价格也差 5 倍以上。** 不谈架构的"节点数"毫无意义。

理解架构，你能回答三个关键问题：

1. **这家机场有没有"护城河"？** 纯转售廉价流量的机场，上游一抖它就崩；自建专线+优化的机场抗风险能力强。
2. **晚高峰为什么卡？** 多半是入口带宽超售、中转链路拥塞，或调度算法没做好。
3. **为什么有的机场解锁 Netflix 而有的不行？** 涉及出口 IP 干净度、原生 IP 与 DNS 解析策略。

## 二、四种主流线路架构对比

现代机场普遍采用以下四种线路类型，从便宜到贵、从裸奔到硬核：

### 1. 直连公网（Direct）

用户 → 运营商网络 → 机场入口节点（境外 VPS）→ 目标网站。

- **优点**：成本最低、延迟理论最低。
- **缺点**：走公网国际出口，晚高峰拥塞严重；IP 易被识别；抗干扰弱。
- **适用**：预算极低、对稳定性无要求的轻度用户。

### 2. 中转架构（Relay / Forward）

用户 → 入口（通常是优化线路 VPS，如 CN2 / 9929 / BGP）→ 中转机 → 落地节点 → 目标网站。

- **优点**：入口用优化线路，规避公网拥塞；落地节点可灵活更换。
- **缺点**：多了至少一跳，若中转机性能差反而更慢；中转机是被攻击/超售高发点。
- **适用**：性价比之选，市面上 80% 的中端机场采用。

### 3. IPLC / IEPL 内网专线

用户 → 入口 → **运营商级内网专线（不进公网）** → 落地 → 目标网站。

- **优点**：全程不暴露在公网，几乎不受国际出口拥塞影响，延迟稳定、晚高峰不卡。
- **缺点**：成本极高，单条 G 口专线月费数万，必然转嫁给价格。
- **适用**：企业、重度用户、对稳定性极致要求者。

### 4. Anycast 入口

用户 → 最近的 Anycast 边缘（全球任一 PoP）→ 骨干网 → 落地。

- **优点**：用户自动接入延迟最低的入口，天然抗 DDoS、抗单点故障。
- **缺点**：运维复杂度高，需要自有 AS 与 BGP 广播能力，只有头部机场玩得起。
- **适用**：高可用场景，是顶级机场的标配能力之一。

**对比速查表：**

| 架构类型 | 相对成本 | 晚高峰稳定性 | 抗封锁 | 延迟 | 典型用户 |
|------|------|------|------|------|------|
| 直连公网 | ¥ | ★ | ★ | 中 | 轻度 |
| 公网中转 | ¥¥ | ★★ | ★★ | 中 | 日常 |
| IPLC/IEPL | ¥¥¥¥ | ★★★★★ | ★★★★ | 低 | 重度/企业 |
| Anycast | ¥¥¥ | ★★★★ | ★★★★ | 低 | 高可用 |

> 💡 经验法则：**看落地 IP 的 AS 归属与 traceroute 跳数**，能大致判断它是直连、中转还是专线。下文脚本会用到。

## 三、传输协议栈：从 Trojan 到 VLESS+Reality

线路决定了"路好不好走"，协议决定了"你怎么伪装成正常流量"。

### 3.1 TLS 伪装原理

现代科学上网协议几乎都建立在 **TLS 1.3** 之上。TLS 是 HTTPS 的同款加密层，这意味着你的代理流量在外层看起来和访问普通网站一模一样 —— 这正是它能长期稳定的根本原因。机场的核心能力之一，就是维护一批**干净、未被标记、支持 SNI 伪装**的入口证书。

### 3.2 Trojan：把"像 HTTPS"做到极致

Trojan 协议的逻辑很简单：**你的流量外层就是标准的 TLS 握手**，服务端收到后若校验通过就转发，否则当作普通 HTTPS 请求丢弃。它不追求"协议混淆"，而是"我本来就是 HTTPS，你没法区分"。

### 3.3 VLESS + Reality：更进一步的指纹对抗

Reality 是 VLESS 的进阶形态，它直接**伪装成访问某个真实存在的网站（如微软、苹果、Cloudflare）**，连自签证书都不需要，而是借用目标站点的真实证书链。这极大提高了被动检测的门槛。

### 3.4 连接复用与 mux

单次 TCP 握手代价很高。通过 **多路复用（mux / connection multiplexing）**，一个 TCP 连接可以承载多条数据流，显著减少握手延迟、提升小文件并发性能。这也是为什么同样的线路，开了 mux 的客户端刷网页明显更跟手。

### 3.5 协议选择建议

| 场景 | 推荐协议 | 理由 |
|------|------|------|
| 最大兼容性 | Trojan / VMess+TLS | 生态成熟、客户端全 |
| 最强抗检测 | VLESS+Reality | 无证书、难被动识别 |
| 极端弱网 | Hysteria2 / TUIC | 基于 QUIC，抗丢包 |
| 移动端省电 | VLESS | 连接管理更轻量 |

## 四、负载均衡与节点调度

一家机场有 100 个节点，但**用户全挤在 3 个热门节点上**，体验照样崩。调度系统才是隐形分水岭。

### 4.1 DNS 轮询 vs 智能调度

- **DNS 轮询**：最原始，同一域名返回不同 IP，简单但无法感知节点负载。
- **智能调度**：根据用户地理位置、节点实时负载、链路质量，动态返回最优入口。需要自建调度服务和健康监测。

### 4.2 BGP / Anycast 调度

头部机场通过 **BGP（边界网关协议）** 广播自己的 IP，配合 Anycast，让全球用户自动连到最近的 PoP。当某个 PoP 故障时，BGP 会撤回路由，流量自动切到健康节点 —— 这是"用户无感知切换"的技术基础。

### 4.3 健康探针与自动摘流

优质机场会对每个节点做**秒级健康探测**（延迟、丢包、解锁状态）。一旦某节点异常，调度系统会在几秒内把它从可用池摘掉，避免用户连上"僵尸节点"。

> 你可以从侧面验证一家机场的调度水平：**半夜和晚高峰分别 traceroute 同一个域名**，如果入口 IP 完全不同且晚高峰明显走专线，说明它做了智能调度。

## 五、CDN 与边缘加速

部分机场会把**订阅分发、配置下发、更新通道**放到 CDN（如 Cloudflare）上，这样：

- 用户下载订阅配置走 CDN 边缘，速度快且抗封锁；
- 即使主站被墙，订阅仍可更新；
- 配合"订阅转换"服务，客户端能自动拿到优化后的节点列表。

这也是为什么**订阅链接的稳定性**往往比节点本身更值得关注 —— 节点天天换，订阅入口必须永远可达。

## 六、一家机场的典型部署拓扑

下面是一家中高端机场的简化拓扑（ASCII）：

```
                         [ 用户设备 ]
                              |
              (智能 DNS / Anycast 入口)
                              |
              +---------------+---------------+
              |               |               |
        [入口节点-A]     [入口节点-B]     [入口节点-C]
        (CN2 GIA)       (9929 优化)      (Anycast)
              |               |               |
              +-------+-------+-------+-------+
                      |  中转骨干网 / IPLC
                      |
            +---------+---------+
            |  负载均衡调度器     |  ← 实时健康监测
            +---------+---------+
                      |
        +------+------+------+------+
        |      |      |      |      |
     [落地HK][落地JP][落地US][落地SG]  ← 各自独立出口 IP
        |      |      |      |
        +------+------+------+------+
                      |
                 [ 目标网站 / 流媒体 ]
```

关键看点：

1. **入口做优化**（CN2/9929/Anycast），解决"第一公里"；
2. **骨干走中转或专线**，解决"中间一公里"拥塞；
3. **落地独立且分散**，解决解锁与单点故障；
4. **调度器统一管控**，解决"人挤人"。

四层都做好的机场，才是真正的"架构硬"。

## 七、用 PowerShell 给机场做"架构体检"

下面这份脚本帮你从架构角度探查一家机场：解析订阅域名、测量入口延迟、traceroute 看线路跳数、检测 DNS 是否泄露。把 `your-subscription-host.com` 换成你机场订阅域名即可。

```powershell
# ===== 机场架构体检脚本 (PowerShell 5.1+ / PowerShell 7) =====
# 用法：将 $hostName 替换为机场订阅/入口域名后运行
$hostName = "your-subscription-host.com"

Write-Host "=== 1. DNS 解析（看入口 IP 与 ASN 归属）===" -ForegroundColor Cyan
try {
    $dns = Resolve-DnsName -Name $hostName -ErrorAction Stop
    $dns | ForEach-Object {
        Write-Host ("  {0} -> {1} ({2})" -f $_.Name, $_.IPAddress, $_.Type)
    }
} catch {
    Write-Host "  DNS 解析失败：$_" -ForegroundColor Red
}

Write-Host "=== 2. 入口延迟 & 跳数（traceroute 看线路类型）===" -ForegroundColor Cyan
try {
    Test-NetConnection -ComputerName $hostName -TraceRoute -InformationLevel Detailed |
        ForEach-Object {
            Write-Host ("  跳数: {0}  平均延迟: {1}ms" -f $_.PingReplyDetails.Count, $_.PingReplyDetails[0].RoundtripTime)
            $_.TraceRoute | ForEach-Object { Write-Host ("    Hop -> {0}" -f $_) }
        }
} catch {
    Write-Host "  Traceroute 失败：$_" -ForegroundColor Red
}

Write-Host "=== 3. 端口连通性（判断入口是否存活）===" -ForegroundColor Cyan
443, 8443, 2053 | ForEach-Object {
    $r = Test-NetConnection -ComputerName $hostName -Port $_ -WarningAction SilentlyContinue
    Write-Host ("  端口 {0}: {1}" -f $_, $(if($r.TcpTestSucceeded){'开放 ✅'}else{'不可达 ❌'}))
}

Write-Host "=== 4. DNS 泄露自检（连接到机场后运行，应只看到机场出口）===" -ForegroundColor Cyan
Write-Host "  请访问 https://clashvip.net 提供的检测页，或在浏览器搜索 'DNS Leak Test' 自查。"
```

**怎么读结果：**

- 入口 IP 属于 `CN2 / 9929 / GIA` 段，且 traceroute 跳数少（<10）→ 优化线路，第一公里好。
- 入口走 `59.43.x / 218.x` 等 CN2 段 → 优质优化。
- 晚高峰延迟比凌晨高 3 倍以上 → 入口或中转超售，架构扛不住。
- 连接机场后 DNS 泄露测试出现本地运营商 → 客户端 DNS 配置有误，需检查。

## 常见问题

### Q: 我是小白，看不懂架构怎么办？

A: 不必全懂，记住三个可操作动作即可：① 晚高峰实测速度（别信标称）；② 看社区真实评价（https://bbs.clashhub.net）；③ 先买月付试水，不满意就换。

### Q: traceroute 看到很多 `* * *` 是坏事吗？

A: 不一定。很多优化节点会屏蔽 ICMP，显示为 `*`，但只要最终能连通、延迟正常就没问题。重点看**最后一两跳的延迟**。

### Q: 为什么同一机场白天快晚上慢？

A: 典型的中转/入口超售表现。晚高峰用户集中，入口带宽被打满。选有多线入口 + 自动调度的机场（如 ClashVIP）能大幅缓解。

### Q: Reality 和 Trojan 哪个更好？

A: 抗检测优先选 Reality（VLESS）；兼容性与生态优先选 Trojan。两者都是现代机场的主流选择，不必纠结。

### Q: 订阅链接为什么重要？

A: 节点天天换，订阅入口（通常走 CDN）必须永远可达，否则你连不上任何节点。优质机场订阅更新稳定，这也是架构的一部分。

### Q: 客户端怎么选？

A: Windows 用 Clash for Windows（https://clash-for-windows.net）；macOS 用 ClashX；Android 用 Clash for Android；iOS 用 Stash / Surge；路由器用 OpenClash / PassWall。
